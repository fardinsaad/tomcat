Six Metrics
Action metrics cover what Tomcat itself performs. Plan metrics extend to the principal’s subsequent steps, so a response can have perfect actions and still fail as a plan.
🎯 Instruction Accuracy binary
Did Tomcat classify the callout correctly as clear or unclear? Scored against the dataset’s Type label.
denominator: 1
💎 Intent Accuracy binary
Did the response identify the gem the principal actually wants? Where several gems are equally consistent, naming any of them counts.
denominator: 1
✅ Action Feasibility fraction
Share of Tomcat’s own actions that are executable in the grid — the key exists, is reachable, and the colour matches the door. Efficiency is not judged here.
denominator: GT agent actions
📈 Action Optimality fraction
Share of Tomcat’s actions that are the optimal ones. A feasible but longer route scores here even though it passed feasibility.
denominator: GT agent actions
🛠️ Plan Feasibility fraction
Share of the full plan — agent actions and the principal’s subsequent unlock and retrieve steps — that is executable.
denominator: GT atomic actions
🧮 Plan Optimality binary
Is the whole action sequence correct and correctly ordered? A plan that passes a key before collecting it fails, however feasible each step looks alone.
denominator: 1

How the denominator is built. GT_atom_count is the number of atomic actions in the ground-truth Actions block — agent actions plus the principal’s. Compound phrases split: “pass two keys” counts as two, not one. A surplus action that substitutes for a ground-truth action of the same type does not enlarge the denominator; a genuinely extra action does.
